# JZRM Mac 桌面应用设计规格

日期：2026-09-30
状态：待 ALEX 审阅

## 1. 目标与边界

JZRM 是 ALEX 个人使用的小说与剧本杀创作工作台。它沿用 StarWriter 已观察到的左侧主导航、作品库、单作品创作空间和 AI 配置的层级逻辑，用 JZRM 自有名称、金毛剪影图标和自有素材实现界面。DeterminFlow 的对话、圆桌讨论、工作流分别融入为全局「助手」「脑暴」弹窗及创作流程提示和画布。

成功标准：能在一部作品内完成「导入灵感或正文 → 提炼大纲、设定和记忆 → 编写小说 → 证据式审校与替换 → 转为多角色剧本杀文本 → 编写组织者手册 → 再审校 → 导出」的闭环。所有生成物必须可人工修改、可回退、可追溯所用模型和输入版本。

首版只面向 macOS 单用户，作品及配置本地保存；AI 创作依赖用户配置的在线模型，不承诺断网时执行 AI 任务。普通编辑、阅读和导出在无网络时仍可使用。

## 2. 信息架构与页面映射

| StarWriter 入口 | JZRM 入口与行为 |
| --- | --- |
| 首页 | 创作概况、最近作品、当前流程步骤、字数与任务入口 |
| 作品库 | 新建、导入、搜索、切换作品；每部作品有独立资料与版本 |
| 阅读空间 | 按作品、卷、章节、角色视角阅读与批注 |
| 作品拆解 | 导入或搜索作品，拆解结构、角色、叙事和文风；生成文风包 |
| 灵感泡泡 | 记录灵感并关联大纲、设定、章节 |
| 角色起名器 | 保留命名辅助能力，并将选用结果写入当前作品设定 |
| 个人小说宇宙 | 小说改编剧本杀 |
| 写作分析 | 审查修改 |
| 成就系统 | AI 润笔 |
| AI 配置 | 供应商、模型、生图模型、Agent、技能、Prompt 和用量 |
| 移动配对 | Agent 技能树 |

全局顶栏提供作品切换、「助手」「脑暴」及「创作流程」入口。助手和脑暴在所有页面均为可收起弹窗，保留当前作品上下文；助手返回的功能建议可直接打开相应页面。流程提示显示当前位置、下一建议步骤和跳转按钮。主导航另增加「垃圾箱」。

**作品内的「大纲」「设定」「记忆」「细纲」「正文」分别是可以单独进入的页面，不在同一页面堆叠，也不做五个只切换面板的标签。**借鉴 StarWriter 的作品侧栏：一级主导航先进入作品；作品左栏用可展开的「创作资料」「分析与发布」「其他」组织二级页面；每个二级页面再以分类按钮进入分级页，操作方式与灵感泡泡的「全部／开书想法／剧情……」相同。页面可有各自的路径、标题、搜索、列表、编辑区和返回位置，刷新或从助手跳转后仍停在目标分级页。

作品内建议树形路径如下：

```text
当前作品
├─ 正文（写作：卷目录 → 章节编辑页；可切换卷引言、阅读与版本）
├─ 创作资料
│  ├─ 大纲（总纲 → 卷纲 → 章纲；树、节奏与提炼）
│  ├─ 细纲（卷 → 章 → 场景／节拍；与大纲、正文双向定位）
│  ├─ 设定概览
│  │  ├─ 人物（档案／分类／关系／属性／技能树／出场）
│  │  ├─ 情绪（角色弧线／章节情绪目标／情绪曲线）
│  │  ├─ 背景与世界观（概览／势力／力量／法则／社会／异能／科技／经济／文化）
│  │  ├─ 地图与地点（地点卡／关系画布／背景图）
│  │  ├─ 时间线（现实事件／回忆／角色知情状态）
│  │  ├─ 伏笔追踪（埋设／揭示／废弃）
│  │  └─ 文风（参数／原则／例句／关联文风包）
│  └─ 记忆（事实关键词／禁忌词／限制词／限制句式／限制语义／限制情景）
├─ 分析与发布（章节评审／读者模拟／发布审查／角色出场／情绪曲线／关系图谱）
├─ 审查修改（整篇／局部／修改计划／版本与导出）
├─ 小说改编剧本杀（改编项目 → 角色本／对齐／线索任务／组织者手册）
└─ 其他（导入设定／导出作品／历史版本／版本快照）
```

正文、大纲、细纲、设定、记忆在一个作品内可互相跳转，但各自保存页面状态。切换作品时，这些页面、阅读位置、改编项目、审校记录和流程进度一起切换，不跨作品混用事实或限制词。当前作品 ID 必须进入页面路径和数据查询，取消当前作品后返回作品库。StarWriter 的其他原有作品内页面按《StarWriter 页面与操作链路核对记录》保留；其中被用户明确替换的入口按本规格替换。

## 3. 作品与编辑数据

每部作品包含元数据、原始导入文件引用、灵感、大纲树、细纲、章节正文、角色、人物关系、情绪线、背景、地点/地图、事件时间线、事实库、记忆规则、参考资料、审校记录、剧本杀改编方案、组织者手册及导出记录。大纲和设定可以手动编辑，也可以从灵感或正文提炼；AI 提炼先展示候选差异，再由用户采纳。灵感泡泡可手动关联或通过 AI 推荐关联。

「记忆」管理关键词、事实、禁忌词、限制词、限制句式、限制语义、限制情景。每条约束有适用范围（全作品、角色、章节、任务）、优先级和来源。内置的“减少模板化表达”预设是可多选、可改的编辑规则；不宣称能判定作者身份。创作时按适用范围组装上下文，超过模型窗口时先压缩并显示采用了哪些资料，不能静默丢弃高优先级事实。

人物关系、世界地图、时间轴先有结构化可编辑数据；调用已配置的图片模型生成对应图像视图，用户可重生成、导出或回到结构化数据修改。图像不是事实来源。

所有 AI 写入采用提案模式：预览、接受、拒绝、局部接受。正文、组织者手册和关键设定有版本快照、撤销和差异对比。失败的模型任务不能覆盖已保存内容。

## 4. 小说改编剧本杀

改编项目绑定一部小说，可设置人数、目标角色、章节范围、预估时长、目标字数、类型侧重和输出结构。输入可包括小说正文、现有剧本杀角色本、线索文件及组织者手册。系统先提炼公共事实和现实事件时间线，再生成各角色第二人称「你」视角；每个角色只接收其应知信息。回忆以独立片段表示，并在每章末用现实时间线事件校准。

改编工作区至少包含：角色视角表、章节对齐矩阵、现实时间线、回忆表、任务与线索分发表、剧情推进、角色文本、组织者手册。对齐检查指出角色在同一事件上的时间、地点、知情状态和因果冲突，并列出源段落及建议。线索可设触发条件、持有人、投放章节、公开/私有、回收事件和替代投放方案。

导入既有剧本杀剧本时，AI 可提出任务、线索投放及剧情优化方案；先展示与原方案的差异和理由，再由用户应用。组织者手册可以从导入手册提炼结构并重写为当前作品版本，也可以完全手写。每章可设置演绎条件、触发时机、失败兜底、DM 提示与禁止提前透露的信息。

补写支持目标字数或时长，并可调情感/推理/机制等类型侧重，以及日常故事、对话、动作、心理描写的增量比例。补写前给出缺口估算和计划，生成后运行事实、角色声线、时间线和线索可见性检查；时长仅作基于用户设定阅读/演绎速度的估算，可手动校准。

## 5. 审查修改与 AI 润笔

整篇审查包含连续性、人物、情绪、叙事、语言、节奏和“AI 味”七项。默认显示《剑来》=90 的用户预设比较标尺；该分值不是客观质量结论。未导入可用参照文本时，仅以用户定义的评价量表审查，明确标注“未做文本相似对比”。可导入小说或剧本杀角色文本作为本地对比对象，选择参与的项目和章节。材料不足时给出缺口和可执行建议，不输出精确综合分。StarWriter 已有的章节评审、发布审查、AI 痕迹报告在 JZRM 中接入同一审校记录与页面层级，不再生成彼此矛盾的重复评分。

审查结果包含分项分数、综合分、证据原文、问题原因、严重度及修订建议。AI 味维度只列出具体的重复结构、套话、过度解释等可编辑现象，不做 AI 作者识别。可让指定 Agent 制定整体修改计划；一键修改先产生预览差异，确认后应用。

局部审校可选编辑器选区或导入文本，依据已导入事实、上下文、人物声线、情绪目标、文风包和限制规则逐条核查。每条问题定位原文，并给出三种修改候选；用户可选择某一种替换、手动改写或跳过。整篇与局部审校均可导出 TXT、DOCX、PDF，导出前选择正文、批注、审校报告与版本。

AI 润笔是单项任务台：续写、减少模板化表达、上下文逻辑对齐、文风强化及用户导入的 Skill。每项明确输入范围、使用 Agent/模型、约束和预览差异。它与正文编辑器内的续写、润色按钮调用同一个任务服务，结果和版本只存一份。Skill 导入仅接收声明式文本模板与元数据，不执行外部脚本；冲突时作品事实和手动禁令优先。

## 6. 作品拆解、搜索与文风仓库

拆解可读取用户导入的文本、用户提供的 URL，或根据一句灵感、作品名、台词、角色名调用配置的搜索服务检索公开结果。搜索结果逐条显示标题、链接、摘要、获取时间和采用/排除选择；总结不可把搜索片段当作整部作品。对不可访问或付费内容仅提示导入用户有权使用的文件。

拆解产生结构化卡片：叙事节奏、视角、场景组织、人物声线、情绪推进、句法倾向和可迁移手法。用户可将其中的抽象特征蒸馏成文风包。仓库以卡片展示名称、精简特征和**新生成**的示例句；悬浮/点击展开详细规则、禁用条件、来源与版本。文风包可编辑、复制、启用到作品或指定 Agent。

随应用预装六个可编辑文风包：当前男频榜前三之一、当前女频榜前三之一、当前红果热播短剧台词趋势、当前抖音/微博/小红书热梗趋势、琼瑶作品的抽象叙事特征、金庸/古龙作品的抽象叙事特征。前四包带来源、采集日期和刷新按钮；无法验证新榜单时保留最近一次已验证版本并标记「待更新」，不假装永久“当前”。所有预置包只保存抽象写法规则和原创示例，不预装作品正文或台词。作品「文风」页和 Agent 均通过文风包 ID 引用同一个仓库记录。

## 7. Agent、助手、脑暴与流程

AI 配置中心管理供应商、模型、图片模型、连接测试、调用用量、Agent 和 Skill。API 密钥存 macOS Keychain，不写入作品文件。每种 Agent 可建多个实例，至少预设策划、搜索、写手、审校、文风、情绪、改编、DM、读者和主管；每个实例配置模型、技能、文风、参考标准、视角、情绪任务及权限范围。「Agent 技能树」是这些同一 Agent 实例的图形管理页，不能维护另一份配置。主管 Agent 根据灵感和当前进度提出下一项任务并选择 Agent，展示理由与预计输入；需要修改作品时仍经用户预览确认。

「助手」支持围绕当前作品对话，引用作品资料时显示来源，并可携带参数跳转功能页。「脑暴」支持选多个 Agent 席位、设议题、轮次、结论与待办；结论可人工采纳为灵感、大纲候选或流程节点，不能直接悄悄改正文。

流程默认节点：灵感 → 小说大纲 → 小说设定 → 小说细纲 → 小说创作 → 审校 → 改编剧本杀 → 再审校修改。画布支持拖动节点、连线、增删模块、配置输入/输出、保存多个流程。节点须校验入口、出口和依赖；「一键配置」保存后，提示弹窗逐步引导并可跳转页面。流程提示是辅助，不强制锁住用户自由编辑。

## 8. 删除、垃圾箱与恢复

全局主导航有「垃圾箱」，顶部可按作品、内容类型、删除时间筛选。分类包括作品；卷与章节正文；大纲与细纲节点；设定（角色、关系、情绪、背景、地点、时间线、伏笔、属性、文风）；记忆规则；灵感泡泡；拆解任务与拆解报告；文风包；剧本杀改编项目、角色本、任务线索、组织者手册；Agent、Skill、Prompt 模板；流程与脑暴记录。凡是 JZRM 内能新建、导入或编辑的持久对象，都必须有可见的删除入口和对应垃圾箱分类；系统预置项不可直接消失，可恢复默认或隐藏后在垃圾箱找回。

普通「删除」只移入垃圾箱。列表、搜索、AI 检索和导出默认排除垃圾箱内容；垃圾箱卡片显示原作品、原分类、原路径、删除时间、关联对象数，并提供预览、恢复、永久删除。支持单项和批量恢复、按分类清空或清空全部；永久删除及清空要再次确认并列明影响。默认不自动清空，不因退出或重新安装而自动抹去垃圾箱。

删除卷、作品或文件夹这类父对象时，子对象随父对象一同进入垃圾箱，以同一个删除批次恢复到原层级；不会留下孤儿章节或场景。单独删除子对象时只移动该子对象。恢复时若原父对象还在垃圾箱，应先恢复父对象或连同父对象恢复；若名称、位置或关联已被占用，则预览冲突并提供改名、恢复到新位置、取消，不覆盖现有内容。引用已删对象的灵感关联、章节链接、Agent 配置和流程节点保留 ID 与「已删除」标记，恢复后重新生效；AI 生成时不得把已删内容当作事实。若引用对象已永久删除，则显示失效引用并允许手工重新绑定。

正文版本与快照是恢复之外的另一层保护：移入垃圾箱保留其版本；恢复一并带回。永久删除需真正清除记录和附件，备份文件不随之自动修改，界面应说明这一点。可在垃圾箱按作品和类型搜索、预览正文摘要、追溯删除来源，支持对误删的一次性撤销提示。

## 9. 桌面架构与数据安全

建议 Electron + React + TypeScript。主进程负责本地数据库、文件导入导出、Keychain、网络请求和更新；渲染进程负责页面、编辑器与画布，经受限 IPC 调用主进程。作品用本地 SQLite 与附件目录保存；长文本按章节与版本组织，支持备份/恢复。联网模型通过统一适配层接入供应商；请求前可查看将发送的章节和参考资料，日志隐藏密钥与正文。

导入优先支持 TXT、Markdown、DOCX、可提取文本的 PDF；扫描版 PDF 需要 OCR 时明确提示。导出支持 TXT、DOCX、PDF。搜索和热榜数据需要用户配置可用服务或使用公开网页来源；访问失败时不伪造结果。界面在首次使用时可无模型配置进入，AI 按钮提示完成配置。

JZRM 建为独立项目，不放入 ALEX Brain Core。作品正文、密钥、导入素材、缓存和源码均不写入规则库。应用在本机处理个人作品，不默认上传至云盘。

## 10. 交付顺序与验收

按可运行增量交付，但目标包含本规格全部模块：

1. 桌面壳、导航、作品库、本地存储、独立的作品分级页、垃圾箱、图标。
2. AI 配置、Agent/Skill、灵感、大纲、设定、记忆、正文与版本。
3. 审查修改、AI 润笔、三案替换、导出。
4. 剧本杀改编、章节对齐、线索、组织者手册与补写。
5. 作品拆解、搜索、文风仓库、助手、脑暴、流程画布、图片视图。
6. 全链路验收、Mac 打包、备份恢复与体验修整。

验收使用至少两部虚构作品验证隔离，分别直接进入大纲、设定、记忆、细纲、正文的独立页面，验证页面刷新、返回、助手跳转与切换作品；至少三名角色和两章事件验证第二人称与时间线，至少一处回忆与线索投放验证知情边界，至少一处审校问题验证原文证据、三案替换和撤销；断网时可编辑和导出、AI 任务给出清楚错误；模型失败或关闭窗口不丢已保存内容。删除验收覆盖每一类可创建对象、父子级联、跨作品隔离、单项恢复、冲突恢复、永久删除确认和备份提示。每个保留的 StarWriter 页面在实现时以实际应用逐页核对交互，未核对页面不得宣称完全一致。

## 11. 已知取舍与待确认

- 界面沿用参考应用的信息层级和交互节奏，但使用 JZRM 自有标识、图标与素材。
- 在线模型调用成本由用户所配置的供应商决定；应用展示任务与用量，不自动执行高成本批处理。
- 《剑来》90 分是用户设定的标尺，比较对象需用户导入或提供可访问来源。
