# 审查修改优化方案与模板

日期：内测01 第2轮。参照：StarWriter 章节评审、墨灵小说（InkSpire）、termo.ai open-novel-writing、彩云小梦等 AI 辅助写作 App 的评审/审校交互。

## 一、调研结论

| 产品 | 评审/修改做法 | 可借鉴点 |
| --- | --- | --- |
| StarWriter | 沉浸式章节评审：正文+综合分+六维+综述+设定偏离+痕迹分析+问题明细（严重/轻微/其他）+定位原文 | 问题分级、定位、沉浸式左右分栏 |
| open-novel-writing | 5 角色加权评审（阅读者/编审/故事家/文学顾问/毒舌读者），分级评分（精品/优秀/良好/合格/重写），P0/P1 红线 | 多角色权重、评分档位、红线分级、规格对照 |
| 墨灵小说 | 拆书逐槽位、万物百科（长期记忆）、真相记忆（伏笔） | 结构化记忆注入、伏笔追踪 |
| 彩云小梦 | 续写/润色/扩写单点任务 | 单项任务台 |

共同结论：好的"审查修改"不是一次性输出一个分数 + 一堆问题，而是
**① 多角色加权评审 → ② 分级评分 → ③ 红线分级 → ④ 规格对照（连贯性） → ⑤ 问题定位 + 逐条替换**。

## 二、当前 JZRM 审查修改的问题

1. 评审是"单一口径"，一个模型一次性给出六维分 + 问题，缺少**角色视角**（读者/编审/故事家各看各的）。
2. 只给原始 0-100 分，缺少**档位语义**（85 分到底能不能发？）。
3. 评审只看正文文本，**不对照该章的大纲/细纲**（这章本来要埋什么钩子、人物要到什么状态、回收哪个伏笔）。
4. 红线（限制词）与评审脱节：限制词只在润笔里多选，评审没有逐条核对"是否触犯 P0 红线"。

## 三、优化建议

1. **多角色加权评审**：一次评审按 5 个角色各出一份意见 + 各自评分，再按权重合成综合分。
2. **分级评分档位**：综合分映射到档位（精品/优秀/良好/合格/重写），显示"可发布/小改可发/需修改/重写"。
3. **红线分级**：评审结果单列"红线命中"（P0 绝对禁止 / P1 建议优化），P0 直接拦、逐条给出原文位置。
4. **规格对照（连贯性检查）**：评审前注入该章的细纲/大纲节点（本章目标、要埋的钩子、人物前后状态、要回收的伏笔），让评审"对照预期"而非"孤立读文"。
5. **保留并强化定位 + 逐条替换**：问题明细带严重度、原文证据、定位、三案改写，替换后自动保存修改前版本。

### 4.2 评审 Prompt 模板（核心段）

```
你是小说审校团，按 5 个角色分别评审本章，再合成综合分：
阅读者(25%)看开篇吸引力/节奏/画面感；编审(25%)看错别字/病句/一致性；
故事家(25%)看剧情逻辑/伏笔/钩子；文学顾问(15%)看语言/人物刻画；
毒舌读者(10%)看套路化/水文/毒点。

对照本章规格（连贯性检查）：
本章目标：____；要埋的钩子：____；人物前后状态：____；要回收的伏笔：____。

红线（P0 绝对禁止）：明显AI词汇、感悟式结尾、感叹式结尾、上帝视角；
（P1 建议优化）：仿佛/宛如堆叠、三句同构排比、段尾总结。

评分档位：90-100精品 / 85-89优秀可发 / 75-84良好小改可发 / 60-74合格需改 / <60重写。
只返回 JSON（见模板 4.1），每个问题 quote 必须逐字来自原文。
```

### 4.3 UI 结构模板

```
审查 · 章节评审
├─ 评审中心（已评审 X/Y 章）
├─ 沉浸式视图
│   ├─ 左：可编辑正文（点问题定位原文）
│   └─ 右：综合分 + 档位标签
│       ├─ 五角色加权分（雷达/条形）
│       ├─ 红线命中（P0 红 / P1 黄）
│       ├─ 连贯性对照（预期 vs 实际）
│       └─ 问题明细（严重/轻微/其他 · 定位 · 三案改写）
```

## 五、实施优先级

- P0：多角色加权评审 + 分级评分档位 + 红线命中（改动评审 Prompt + 结果渲染，成本低、收益大）。
- P1：规格对照（需读取该章大纲/细纲/伏笔节点，作为连贯性检查注入）。
- P2：五角色雷达图（可后置，先做条形/文字即可）。
